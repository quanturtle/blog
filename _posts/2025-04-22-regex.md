## `import re`
Python's regex library is called [re](https://docs.python.org/3/library/re.html).

It contains all of the necessary components to start processing text data.

Can process Unicode strings (str) as well as 8-bit strings (bytes).
Unicode strings and 8-bit strings cannot be mixed: that is, you cannot match a Unicode string with a bytes pattern or vice-versa.

Due to escape characters used in python and regex are the same is hard to escape strings `\\`
backslashes are not handled in any special way in a string literal prefixed with 'r'
that's why you write `r"something"`.

Regular expressions can be concatenated to form new regular expressions; if `A` and `B` are both regular expressions, then `AB` is also a regular expression

Regular expressions can contain both special and ordinary characters.

Repetition operators or quantifiers (`*`, `+`, `?`, `{m,n}`, etc) cannot be directly nested.
This avoids ambiguity with the non-greedy modifier suffix `?`, and with other modifiers in other implementations.

## Types
### Special characters
`.`  - Matches any single character (except newline, `\n`).  
`^`  - Matches the start of a string.  
`$`  - Matches the end of a string. (what delineates the end of a string when using `$`?)

`\`  - Escapes special characters.  
`\n` - Matches a newline character.  
`\r` - Matches a carriage return character.  
`\t` - Matches a tab character.


### Actual types
* `\d` - Matches any digit (0-9)  
    * `digits = "0123456789"`
* `\w` - Matches any word character (alphanumeric plus underscore).
    * `upper_char = "ABCDEFGHIJKLMNOPQRSTUVWXYZ"`
    * `lower_char = "abcdefghijklmnopqrstuvwxyz"`
    * `underscore = "_"`
* `\s` - Matches any whitespace character.
    * `space = " "`
* `\D` - Matches any non-digit character.
* `\W` - Matches any non-word character.
* `\S` - Matches any non-whitespace character.


### Quantifiers
![]({{ site.baseurl }}/img/regex/regex_quantifiers.png)

`?` - Zero or one occurrence of the preceding character or group.  
`+` - One or more occurrences of the preceding character or group.  
`*` - Zero or more occurrences of the preceding character or group.

`{n}` - Exactly `n` occurrences of the preceding character or group.  
`{n, m}` - At least `n` and at most `m` occurrences of the preceding character or group.


### Logic
* `[...]` - Matches any single character within the brackets.
* `(...)` - Groups a pattern (for backreferences and capturing).
* `|`     - Matches either the preceding or following pattern.
* `(?:...)` - Non-capturing group: groups a pattern without saving a backreference.


### Lookahead & Lookbehind
* Direction: `Lookahead assertions` check the future, while `Lookbehind assertions` check the past.
* Assertion: `Negative assertions` check that the pattern does not match, while `Positive assertions` check that the pattern matches.

* `(?=...)`  (positive lookahead)
* `(?!...)`  (negative lookahead)
* `(?<!...)` (negative lookbehind)
* `(?<=...)` (positive lookbehind)


### Mode flags
* `re.NOFLAG`
    * No flag
* `re.ASCII` (`re.A`)
    * restrict `\w`, `\d`, `\s`, `\b` (and their negations) to `ASCII` only
* `re.IGNORECASE` (`re.I`)
    * `a` will match `a` and `A`
* `re.LOCALE` (`re.L`)
    * something
* `re.MULTILINE` (`re.M`)
    * makes `^` and `$` match at the start/end of every line, not just the whole string
* `re.DOTALL` (`re.S`)
    * enables `.` to match `\n`
* `re.UNICODE` (`re.U`)
    * make `\w`, `\d`, `\s` match `Unicode` characters (already the default for `str` patterns)
* `re.VERBOSE` (`re.X`)
    * more detail


### Python Functions
* `re.compile(pattern, flags=0)`
* `re.search(pattern, string, flags=0)`
* `re.match(pattern, string, flags=0)`
* `re.fullmatch(pattern, string, flags=0)`
* `re.split(pattern, string, maxsplit=0, flags=0)`
* `re.findall(pattern, string, flags=0)`
* `re.finditer(pattern, string, flags=0)`
* `re.sub(pattern, repl, string, count=0, flags=0)`
* `re.escape(pattern)`


### `search()` vs. `match()` vs `fullmatch()`
Python offers different primitive operations based on regular expressions:

* `re.match()` checks for a match only at the beginning of the string
* `re.search()` checks for a match anywhere in the string (this is what Perl does by default)
* `re.fullmatch()` checks for entire string to be a match

For example:
```python
re.match("c", "abcdef")                             # No match
>> 

re.search("c", "abcdef")                            # Match
>> <re.Match object; span=(2, 3), match='c'>

re.fullmatch("p.*n", "python")                      # Match
>> <re.Match object; span=(0, 6), match='python'>

re.fullmatch("r.*n", "python")                      # No match
```


## How to think about regex
1. what does it contain? alphabetic, numeric, alphanumeric
2. how does it look? what is its structure?
3. how many of each? select appropriate modifier
4. what conditions? before/after another pattern

Say we want to build a regex expression to tell us if a string is a valid email address:

1. what does it contain? 
```
username:   letters + numbers + symbols
@:          an @ symbol
domain:     letters + numbers + symbols
.:          period between domain and TLD
TLD:        letters (com, edu, gov, country TLDs, etc)
```

2. how does it look? its structure looks something like this:
```
[           username          ] @ [           domain          ] \. [   TLD   ]
[ letters + numbers + symbols ] @ [ letters + numbers symbols ] \. [ letters ]
```
3. how many of each?
```
[     username      ]         @         [      domain       ] \. [     TLD     ]
[ any number (many) ]   exactly one @   [ any number (many) ] \. [ 2/3 letters ]
```

4. what conditions? let's say that we only want `.com` or `.edu` email addresses
```
# pseudocode
com_pattern     = username + @ + domain + . + com
edu_pattern     = username + @ + domain + . + edu

my_string IF address FOLLOWS com_pattern OR edu_pattern else None

# expression with options
joint_pattern   = username + @ + domain + . + [com|edu]

my_string IF address FOLLOWS joint_pattern else None
```


### Put the example together
```
username:   a variable number of alphanumeric symbols   ->  \w+
@:          exactly one @ symbol                        ->  @
domain:     a variable number of alphanumeric symbols   ->  \w+
.:          exactly one . period                        ->  \.
TLD:        choice between com or edu                    -> (?:com|edu)
```
```
\w+@\w+\.(?:com|edu)
```

Two things that are easy to get wrong here:

* `\w+` matches one or more *word* characters. `\.` is an **escaped literal dot**, so `\.+` would match one or more periods, which is not what we want for the username/domain.
* `(?:com|edu)` is real alternation. `[com|edu]` is a **character class** that matches a single character from the set `c o m | e d u`, which is also not what we want.

Test it:
`re.match` only looks at the **start** of the string, and our string starts with `!@#$`, so it would return `None`. To scan the whole string and collect every hit we use `re.finditer` (or `re.findall`):

```python
import re

pattern = r"\w+@\w+\.(?:com|edu)"

jumbled_string = "!@#$alvaro@example.comjansdif12;'hello@world.edu~=-$123"

for match in re.finditer(pattern, jumbled_string):
    print(match.group())
```
```
>> alvaro@example.com
>> hello@world.edu
```
